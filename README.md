# EyeCare AI

AI-powered eye health assistant for Android. Tracks screen time, detects blinks, gives 20-20-20 reminders, and uses on-device AI to suggest eye-friendly habits.

## Why this exists

Phones don’t care about your eyes. This app does:
- reminds you to look away,
- watches how often you blink,
- estimates how much blue light you’re getting,
- and keeps a running eye-health score so it’s not just another timer.

It is distributed as a **sideloaded APK via GitHub Releases**. Auto-update is built in.

## Features

- **Eye health score** — daily/weekly score from blink rate, screen time, break compliance
- **20-20-20 reminders** — look 20 feet away for 20 seconds every 20 minutes
- **Blink detection** — camera-based blink counting with activity compensation
- **Screen time tracking** — foreground app usage grouped by category
- **Blue light filter** — adjustable intensity, plus a brightness-tips helper
- **Dark mode** — light, dark, or match-system
- **AI suggestions** — NVIDIA NIM-backed chat suggestions (EyeChatService)
- **Stats & habits** — charts, streaks, and habit checklists
- **Auto-update** — checks GitHub Releases for newer builds and prompts install

## Releases & auto-update

APK builds are generated by GitHub Actions on every push to `main`.

- **Releases:** [GitHub Releases](https://github.com/Supertime1236/eye_care_ai/releases)
- **Build numbering:** `build-<run_number>`
- **Version in app:** `pubspec.yaml` `version: 1.2.1+alpha`
- **Update mechanism:** `lib/services/update_service.dart` compares installed `versionCode` against the newest GitHub Release tag

### Install a release

1. Download the latest `.apk` from Releases
2. On Android: allow installs from this browser/file manager
3. Open the APK and follow prompts
4. If the app is already installed with the same signing key, it upgrades in place

> If you hit “package conflicts with existing version”, uninstall the old build first.

## Local build

```bash
flutter pub get
flutter build apk --release
```

### Release signing (local)

Release signing uses `android/key.properties` + `android/app/release-keystore.jks`. Both are gitignored. CI uses equivalent values stored as GitHub repo secrets.
